# Best Foot Forward — Project Instructions (Antigravity CLI)

## Session Startup
At the start of every conversation, before responding to the user's first message:
1. Read `memory/project_status.md` for the greeting (count + last app).
2. Greet the user with a single line: **"Ready. [N] applications complete. Last: [Company] — [Role]."** Derive both values from `memory/project_status.md` — no DB query needed.
3. Then respond to whatever the user asked.

## Session Hygiene — Reset/Clear
After completing any major unit of work (resume generated, interview prep doc saved, evaluate-job run, long conversation resolved), suggest clearing the context:
> "Good stopping point — worth running the `cleanup` skill then using `/clear` or `/new` before we continue."
Once per natural break. Never mid-task. Don't repeat if already suggested recently.

**Natural language routing** — the following trigger the named workflow:
- User pastes a job description (long text block) or provides a JD file path → run **evaluate-job** workflow
- User says "tailor", "tailor for [X]", or "let's tailor" → run **resume-tailor** workflow
- User says "prep", "interview prep", or "prep for [X]" → run **interview-prep** workflow
- User says "screen", "screen prep", or "screening for [X]" → run **interview-prep** workflow (screen variant)
- User says "capture a story", "add a story", "record a situation", or "star story" → run **star-story** workflow
- User says "practice", "practice interview", "mock interview", "drill questions for [X]", or "let's practice for [X]" → run **practice-interview** workflow
- User says "got a pass from [X]", "got a decline from [X]", "got a rejection from [X]", "[X] passed", "[X] declined", or "[X] rejected me" → **log the pass**: look up the application by company name, set `status='rejected'`, `stage='rejection'` (if no later stage already set), `concluded_at=date('now')`; refresh the Logseq page with `python3 -m best_foot_forward.utils.export_graph --only '[X]'`; then show a one-line comparison: stage reached, days from apply to pass, and avg days to pass across all declined applications. Then run any post-rejection hooks (see below).

## Post-rejection hooks
After logging any rejection, scan these directories in order and execute every `.md` hook file found:
1. `.claude/hooks/on_rejection/*.md` — committed hooks (shared with the repo)
2. `.claude/hooks/on_rejection/local/*.md` — personal hooks (gitignored, travel with the clone)
3. `data/hooks/on_rejection/*.md` — personal hooks (gitignored, travel with the data dir)

Each hook file is self-contained: it names its requirements and gives instructions to follow. If a hook's requirements aren't met, skip it silently. Run all hooks that apply before reporting back to the user.

## Post-application hooks
After both .docx files are generated in the resume-tailor workflow, scan these directories in order and execute every `.md` hook file found:
1. `.claude/hooks/on_application/*.md` — committed hooks
2. `.claude/hooks/on_application/local/*.md` — personal hooks
3. `data/hooks/on_application/*.md` — personal hooks

## Output Conventions
- Output directory: same folder as the source JD file (`JD_FILE_PATH` in `data/session/resume_data.py` / `data/session/letter_data.py`)
- Resume file name: `{First Last} Resume - {Company} {Role}.docx`
- Letter file name: `{First Last} Cover Letter - {Company} {Role}.docx`
- Formatting defaults: Calibri 11pt, Margins: 0.75 inches, Target length: 2 pages

## Database and Caches
- `data/best_foot_forward.db` is the SQLite source of truth. JSON caches (`_bullets.json`, `_skills.json`, etc.) are generated artifacts — edit via SQLite, not directly.
- After any direct DB edit, run `python3 src/best_foot_forward/utils/export_cache.py` to regenerate all JSON caches.
- The `file_registry` table tracks every file BFF creates or discovers, linked to the generating jd/application. Run `python3 src/best_foot_forward/utils/sync_files.py` to backfill existing files; `--check-orphans` to detect drift.

## Logseq graph (bff)
The company/application/prep/notes layer is mirrored to a Logseq graph at `data/BestFootForward/` (the `bff` MCP graph).
- **DB → pages:** `python3 -m best_foot_forward.utils.export_graph [--only '<Company>']` — writes company entity + `<Company>/<Role>/Application|Prep|Notes` pages. `--only` refreshes one company. Never run `rm pages/*.md`.
- **Pages → DB:** `python3 -m best_foot_forward.utils.reconcile_graph [--dry-run]` — pulls hand-edited page properties back into DB, keyed on `bff-jd-id`/`bff-application-id`. Run this before DB-backed reports.
- **Dashboards:** `python3 -m best_foot_forward.utils.generate_home` — regenerates Home page.

## Bullet and Skills Library
- Read `data/_bullets.json` (the full catalog — there is no per-track split; ADR-0009
  removed it) at start of tailoring. Tracks are freeform tags, not an enum; bullet
  selection is delegated to a subagent against the full library.
- Load `data/_bullets_conditional.json` only when JD calls for special conditions (frontend/React, multilingual, Node.js, pre-2011).
- 15-year rule: Experience from before 2011 (pre-2011) should only appear when it directly addresses a specific gap or explicit requirement.
- When new bullets/skills are created, insert them into SQLite and run `export_cache.py`.

## JD file conventions
- JD files live at `data/BestFootForward/assets/{Company}/{Role_Slug}/{Company}JobDesc.txt`.
- When a JD arrives as text or URL: create the directory, write JD text to `{Company}JobDesc.txt`, use that path as `JD_FILE_PATH`.
- After generation, the `PostToolUse` hook running via `.agents/hooks/post_tool_use.py` automatically runs `track_application.py`.
- Run `python3 src/best_foot_forward/utils/scan_jds.py data/BestFootForward/assets` to register the new JD.
- Update role in DB: `UPDATE jds SET role='<actual role>' WHERE file_path='<path>'`.

## Workflows Detail
Please see the workspace instruction files in `.claude/commands/` or `.agents/skills/` for step-by-step guidance on each workflow:
- **evaluate-job**: compatibility scoring across 5 dimensions (Technical, Seniority, Domain, Depth, Gap risk).
- **resume-tailor**: guided question/answer tailoring from resume/letter sources, writes session python files, builds .docx.
- **interview-prep** / **star-story** / **practice-interview** / **cleanup**: see corresponding markdown instruction files in `.claude/commands/`.
